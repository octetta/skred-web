Why Audio is Weird & Hard

  • Hard-Realtime Audio Threads
  • Unbounded Latency = Glitches
  • BEAM vs Audio
  • The Decoupled Solution
[T+05:00 | Hard-realtime constraints] 1. Hard-Realtime Audio Threads: Zero syscalls, zero malloc/free, zero mutexes, zero GC pauses. 2. Unbounded Latency = Glitches: Even a 1ms hitch causes instant clicks and buffer underruns. 3. BEAM vs Audio: BEAM is built for concurrency and fault tolerance, not microsecond sample render callbacks. 4. The Decoupled Solution: Let C crunch lock-free, zero-alloc DSP math; let the BEAM conduct the orchestra!

Orchestrating from the BEAM

Option 1: Managed Port (open_port)

  • OTP Supervision Tree
  • Stdio Pipes Lifecycle
  • Linked Process Fate

Option 2: UDP Daemon (gen_udp)

  • Detached Background Process
  • True Crash Isolation
  • Zero-Dropout Hot-Reloading

Hardware MIDI Controllers → BEAM Actors

[Q&A Backup | Port vs UDP Orchestration] 1. Option 1 (open_port): Supervised directly in OTP tree via stdio pipes. Linked process fate: crash together, restart together. 2. Option 2 (gen_udp): Detached headless daemon. Complete crash isolation: you can restart or hot-upgrade BEAM nodes without dropping audio buffers. 3. Hardware Integration: MIDI hardware controllers map into BEAM actors and broadcast skode strings in real time.
