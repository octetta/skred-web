Pulp

Adding audio to your BEAM apps doesn't have to be hard.


(Click before presentation)

1. The Hook

Everything you've heard is generated in real-time.

The engine uses < 1MB of RAM.

It is driven entirely by tiny strings of text.

2. The Problem

Audio programming is usually terrifying.

  • Frontend: Complex WebAudio JS graphs.
  • Backend: Thread-blocking, GC pauses, DSP math.


"If your Phoenix server pauses for garbage collection, the audio glitches."

3. The BEAM-like Solution

Pulp is designed exactly like an Erlang/Elixir Actor.

  • Message Passing: Send immutable strings ("v0 f440 a0 l1").
  • Isolated State: The audio thread is lock-free and never parses text or allocates memory.
  • Fault Tolerant: If your Elixir backend crashes, Pulp keeps playing.

4. Zero to Sound

We can control it via UDP from Elixir, or via WebSockets to WASM.

Try the REPL below!



# In Elixir
udp_socket = :gen_udp.open(0)
:gen_udp.send(udp_socket, 'localhost', 8000, "v0 f440 a0 l1")

5. The Inspiration

What will you build?

  • Multiplayer Games: Phoenix Channels broadcasting tiny Skode strings to trigger WASM sound effects for all players.
