SLIDE 04 T+05:00 (3m)
Why Audio is Weird & Hard
TAKEAWAY: Hard-realtime = ZERO syscalls & ZERO allocs in render loop.
  • Audio threads hate malloc/free, mutexes, file/socket I/O, GC pauses.
  • 1ms unbounded latency = instant audible clicks & underruns.
  • BEAM is built for concurrency, not microsecond sample callbacks.
  • Decoupled Solution: C does DSP math; BEAM conducts the orchestra.
SLIDE 05 T+08:00 (5m)
Architecture: One Engine, Two Transports
TAKEAWAY: Exactly the same C DSP core across Web and Native.
  • Pure C Core: Lock-free, zero-alloc audio loop driven by text commands.
  • Target A (Browser / WASM): Zero-install sandbox on any device right now.
  • Target B (Native BEAM): Headless server daemon for Linux, Pis, rigs.
SLIDE 06 T+13:00 (5m)
Orchestrating from the BEAM
TAKEAWAY: Managed Port vs Detached UDP Daemon crash isolation.
  • Option 1 (Port open_port): OTP tree supervised, stdio pipes.
  • Option 2 (UDP gen_udp): Crash isolation! Kill/reload BEAM node without dropping audio buffers.
  • MIDI hardware controllers map cleanly to BEAM actors.
