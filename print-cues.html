SLIDE 03 T+05:00 (3m)
Why Audio is Weird & Hard
TAKEAWAY: Hard-realtime = ZERO syscalls & ZERO allocs in render loop.
  • Hard-Realtime Audio Threads: Zero syscalls, zero malloc/free, zero mutexes, zero GC pauses.
  • Unbounded Latency = Glitches: Even a 1ms hitch causes instant clicks & buffer underruns.
  • BEAM vs Audio: BEAM is built for concurrency, not microsecond sample callbacks.
  • The Decoupled Solution: Let C crunch lock-free, zero-alloc DSP math; let the BEAM conduct the orchestra!
SLIDE 04 T+08:00 (5m)
Architecture: One Engine, Two Transports
TAKEAWAY: Exactly the same C DSP core across Web and Native.
  • Pure C Engine Core: Lock-free, zero-alloc audio loop driven by text commands.
  • Target A: Browser (WASM): Zero-install audio sandbox. Runs right in the browser on everyone's phones and laptops today via WebAssembly.
  • Target B: Native BEAM: Ultra-low-latency headless audio engine for desktop, Linux servers, Raspberry Pis, and live performance rigs.
